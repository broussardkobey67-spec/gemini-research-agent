# What are the main differences between REST and GraphQL APIs?

REST and GraphQL are two approaches to building web APIs, and they differ most
in **how clients request data**.

- **Data fetching.** REST exposes multiple endpoints, each returning a fixed
  data shape, which often leads to over-fetching (getting more than you need) or
  under-fetching (needing several round-trips) [1][2]. GraphQL exposes a single
  endpoint and lets the client specify exactly which fields it wants in one
  query [1][3].
- **Versioning.** REST APIs are commonly versioned via the URL (e.g. `/v2/`),
  whereas GraphQL favours evolving a single schema and deprecating fields over
  time instead of cutting new versions [2].
- **Caching.** REST benefits from mature HTTP caching at the URL level out of
  the box; GraphQL typically needs client-side or application-level caching
  because most requests are POSTs to one endpoint [2][3].
- **Tradeoffs.** REST is simpler, well-understood, and great for straightforward
  resource access. GraphQL shines when clients are diverse (mobile + web) or
  data is deeply relational, at the cost of added server-side complexity [3].

In short: choose REST for simple, cache-friendly resource APIs; choose GraphQL
when clients need flexible, precise control over the data they fetch [1][2][3].
